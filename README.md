# VEGA — мануальный обменник BTC & LTC

Telegram Web App в стиле официального клиента VEGA (сине-бирюзовая «аврора») + админ-бот,
через который оператор управляет всем в реальном времени.

## Что внутри

- **Web App для клиентов**: обмен RUB → BTC/LTC, живой пересчёт по курсу, статусы заявки
  («ищем реквизиты» → реквизиты и сумма → «я оплатил» → подтверждение → завершено),
  личный кабинет с историей обменов, реферальная программа, инфо-раздел с контактами.
- **Админ-бот**: заявки приходят всем администраторам в Telegram; оператор выдаёт реквизиты,
  меняет сумму, подтверждает оплату, отклоняет. Все настройки (курсы BTC/LTC, лимиты,
  онлайн/оффлайн, объявление, реф. процент, контакты) меняются из бота и **сразу**
  отображаются на сайте.
- **Авторазвёртывание**: ввести нужно только `BOT_TOKEN` и `ADMIN_ID` — база, дефолтные
  курсы, публичная ссылка и кнопка меню Telegram создаются/прописываются автоматически.

## Запуск (2 переменные)

```bash
npm install
# .env:
BOT_TOKEN=1234567890:AA...   # токен от @BotFather
ADMIN_ID=123456789           # ваш TG ID (узнать: @userinfobot)
npm start                    # или: pm2 start server.js --name vega
```

Готово. Сайт раздаётся **этим же процессом**. Порт берётся сам: `SERVER_PORT` (бот-хостинги / Pterodactyl) → `PORT` → `8080`.

### Сайт пишет «Bot is running»

Это **не VEGA**, а заглушка панели (часто Bot-Hosting.net): запрос не доходит до Node, потому что процесс слушает не тот порт или запущен не тот файл.

1. **Startup / Main File** = `index.js` (подойдут также `server.js` и `bot.js` в корне). Не указывайте `src/bot.js` — тогда сайт не поднимется.
2. **Не задавайте `PORT=8080` вручную** в `.env` и в переменных панели. Хостинг сам подставит `SERVER_PORT` — VEGA его подхватит.
3. Перезапустите сервер. В логах должно быть:
   `веб-сервер слушает 0.0.0.0:<порт> (источник порта: SERVER_PORT)`
4. Откройте **IP:порт из Allocations** или домен вида `ID.site.bot-hosting.cloud` — должна открыться страница VEGA.
5. Telegram Mini App работает только по **HTTPS**. На Bot-Hosting.net проще всего Cloudflare Flexible (CNAME на `ID.site.bot-hosting.cloud`), либо задайте `PUBLIC_URL=https://ваш-домен`.

### Автонастройка

1. База `data/db.json` создаётся при первом запуске (курсы по умолчанию — меняйте в ⚙️ бота).
2. Публичный адрес сайта определяется **автоматически** при первом открытии страницы
   (по заголовку Host) и сразу прописывается в кнопку меню Telegram (`setChatMenuButton`).
3. Бот присылает каждому админу онбординг-сообщение после успешной доставки. Админ должен сначала открыть бота и нажать `/start`.

> Telegram требует HTTPS для Web App: поднимите сайт за любым SSL-прокси
> (Cloudflare Tunnel, nginx + certbot, proxy вашего бот-хоста) и просто откройте его один
> раз — адрес подхватится сам. При желании можно задать `PUBLIC_URL=https://...` вручную.

### Несколько администраторов

Старый `ADMIN_ID` продолжает работать без изменений. Для нескольких владельцев
можно задать `ADMIN_IDS=123456789,987654321` (списки `ADMIN_ID` и `ADMIN_IDS`
объединяются, повторы удаляются). Используйте числовые **Telegram ID пользователей**,
не `@username` и не ID групп. После изменения окружения перезапустите сервер.

В личном чате бота владелец может управлять дополнительными операторами без перезапуска:

- `/admins` или кнопка **👥 Админы** — список и инструкции;
- `/addadmin 987654321` — добавить оператора;
- `/removeadmin 987654321` — отозвать доступ.

Все админы могут обрабатывать заявки и менять настройки обменника. Только владельцы
из окружения могут добавлять/удалять операторов; владельцев нельзя удалить через бота.
Управление доступно только в **личном чате**. Каждый новый админ должен нажать `/start`
в боте, иначе Telegram не позволит отправлять ему уведомления.

Добавленные операторы сохраняются в `data/db.json`. Новые заявки, их статусы и
уведомления «Я оплатил» доставляются всем админам, с отдельной карточкой для каждого.
Блокировка бота одним получателем не препятствует доставке остальным. Активные заявки
доступны через меню, в том числе новому оператору; при запуске бот обновляет их карточки.
Если другой оператор или клиент уже изменил заявку, устаревший ввод не применяется.

> Запускайте **один процесс** `npm start`: Web App и бот используют общую JSON-базу
> в памяти. Не запускайте `src/bot.js` отдельно и не используйте несколько реплик/PM2
> cluster с этой базой. Для сохранения данных при обновлении храните `data/` на постоянном
> диске (или задайте `DATA_DIR`); не удаляйте существующий `db.json`.

### Демо-режим (превью без бота)

Если запустить без `.env` (`npm start`), сайт работает в демо-режиме: клиентский флоу
полностью доступен, а роль оператора выполняет кнопка «🛠 оператор» в правом нижнем углу.
В продакшене (с `BOT_TOKEN`) эти демо-эндпоинты отключаются — оператор работает через бота.

## Флоу обмена

1. Клиент заходит в Web App, вводит сумму в ₽ или в крипте (второе поле считается автоматически — итоговая сумма к оплате видна сразу), выбирает BTC/LTC, указывает кошелёк.
2. Жмёт «Найти реквизиты» → видит анимацию поиска; оператору в бот приходит заявка.
3. Оператор жмёт «💳 Выдать реквизиты». Бот показывает сумму заявки. Если нужна другая
   сумма, **до отправки реквизитов** нажмите «✏️ Сначала изменить сумму» и введите её.
   Затем отправьте реквизиты одним сообщением (до 900 символов).
4. Реквизиты, сумма и статус «Ожидает оплаты» сохраняются **одновременно** — дополнительное
   сообщение с суммой не требуется. Клиент видит их в приложении при следующем обновлении
   (обычно до 3 секунд) и получает личное уведомление, если Telegram разрешает боту писать ему.
   Он переводит указанную сумму и жмёт «Я оплатил».
5. Оператор проверяет поступление и жмёт «✅ Подтвердить и завершить» — бот присылает
   кошелёк и сумму криптовалюты для ручной отправки; клиент видит успех.

Если личное уведомление не доставлено (клиент не запускал или заблокировал бота),
оператор увидит предупреждение, но реквизиты всё равно доступны в Web App. До отметки
«Я оплатил» сумму можно изменить кнопкой «✏️ Изменить сумму». `/cancel` отменяет текущий
ввод оператора, не саму заявку.

Приложение запрашивает статус независимо от настроек, не кэширует API, показывает
ошибку связи и повторяет обновление. При возвращении в Mini App или восстановлении
сети запрос выполняется сразу. После перезагрузки активная заявка восстанавливается
из истории пользователя.

## Рефералка

Каждый клиент получает ссылку `https://t.me/<бот>?startapp=ref<ID>` (вкладка «Рефералы»).
При первом входе по ссылке реферер закрепляется навсегда; счётчик и бонусный процент
(`🎁 Реф. %` в настройках бота) отображаются в ЛК. В заявке оператор видит, кто привёл клиента.

## Структура

```
server.js        точка входа
src/config.js    .env (BOT_TOKEN и ADMIN_ID либо ADMIN_IDS)
src/admins.js    владельцы из окружения и операторы из JSON-базы
src/store.js     JSON-база (data/db.json), атомарные записи
src/web.js       Express: API + раздача Web App + автоопределение URL
src/bot.js       grammy-бот оператора (заявки, настройки, статистика)
src/validate.js  проверка initData по схеме Telegram (HMAC)
public/          Web App (index.html, app.js, style.css, bg.jpg)
```

Безопасность: каждый запрос клиента проверяется по `initData` (HMAC-SHA256, секрет из
токена бота); ЛК и заявки доступны только владельцу.

## Проверки

```bash
npm ci
npm run check
npm test
```

Тесты проверяют обработчики grammY с подменённым Telegram API, настоящий HTTP API
с подписанным `initData`, совместимость старой базы, права и сохранение админов,
доставку/ошибки уведомлений, конфликты операторов и клиентское обновление в jsdom.
Реальный токен, Telegram и рабочая база для тестов не используются.

После выкладки проверьте на живом боте: два админа нажимают `/start`, клиент создаёт
заявку, один админ выдаёт реквизиты, клиент видит их без перезагрузки и нажимает
«Я оплатил», оба админа получают уведомление. Проверьте также повторное открытие Mini App.
